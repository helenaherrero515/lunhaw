# Release Runbook — Lunhaw 1.0 (public web release)

**Owner:** HLN · **Last updated:** 2026-11-08 · Closes the MR milestone (D-MR-01, E-MR-01, E-MR-02).

This is the one place that says how Lunhaw goes live and stays live. Architecture decisions live in
[ADR-001](decisions/ADR-001-cloud-architecture.md); data rules in [PRD](prd.md) (`INV-001`, `BR-001`).

## 1. What ships in 1.0

| Piece | Where | Notes |
|---|---|---|
| Website (`/`, `/home`, `/privacy`, `/terms`) | Cloudflare Pages, static export of `apps/web` | `/explore` (early prototype) redirects to `/home` |
| API | Cloudflare Worker `lunhaw-api-production` (`apps/api`) | Reads the `public_places` view; refuses to serve fixtures in production (503) |
| Database + accounts | Supabase (Postgres + PostGIS + Auth) | Migrations in `supabase/migrations`, applied with `supabase db push` |

**Data at launch** (migration `00014`, generated by `scripts/data/build-public-release-seed.mjs`):
26 places (19 city/national libraries, 7 parks and gardens). Locations are labelled **Estimate** until a person
confirms them; opening hours, amenities and Green Index show **Not available yet**. The 17 barangay reading centers
are held back until someone confirms they exist. Nothing is labelled **Verified** at launch.

**Known limits at launch:** saved places stay on the user's device (no account sync); public-transport routes and
fares are not shown ("we won't guess them"); walking times are straight-line estimates; account deletion and newsletter
unsubscribes are handled by email (see §6).

## 2. One-time setup (needs your accounts)

### 2.1 Supabase
1. Create a project at <https://supabase.com/dashboard> (region: **Southeast Asia (Singapore)**, closest to Metro Manila).
   Save the **database password**.
2. Note from *Project Settings → API*: the **Project URL**, the **anon** key and the **service_role** key. The
   service_role key is a secret: never put it in the website.
3. Note the **project ref** (the `xxxx` in `https://xxxx.supabase.co`) and create a **personal access token** at
   <https://supabase.com/dashboard/account/tokens>.
4. *Authentication → URL Configuration*: Site URL `https://lunhaw.pages.dev`; add Redirect URL `https://lunhaw.pages.dev/home`.
5. *Authentication → Providers → Email*: keep **Confirm email** on.
6. **Custom SMTP is required before launch.** Supabase's built-in mailer only delivers to your own team's addresses
   and is heavily rate-limited, so the public would never receive confirmation emails. Under *Authentication → Emails →
   SMTP Settings*, add a sender, e.g. a transactional provider's free tier (Resend, Brevo) or Gmail SMTP with an app
   password (smtp.gmail.com:587, about 500 emails/day).

### 2.2 Cloudflare
1. Create or sign in to a Cloudflare account; note the **Account ID** (dashboard sidebar).
2. Create an **API token** (*My Profile → API Tokens → Create Token → "Edit Cloudflare Workers"* template, plus
   *Account → Cloudflare Pages → Edit*).
3. Locally, `pnpm --filter @lunhaw/api exec wrangler login` lets you run the first deploy by hand (§3).

### 2.3 GitHub (Settings → Secrets and variables → Actions)

| Name | Kind | Value |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | secret | token from 2.2 |
| `CLOUDFLARE_ACCOUNT_ID` | secret | account ID from 2.2 |
| `SUPABASE_ACCESS_TOKEN` | secret | personal access token from 2.1 |
| `SUPABASE_DB_PASSWORD` | secret | database password from 2.1 |
| `SUPABASE_SERVICE_ROLE_KEY` | secret | service_role key from 2.1 |
| `SUPABASE_PROJECT_REF` | variable | project ref |
| `SUPABASE_URL` | variable | `https://<ref>.supabase.co` |
| `SUPABASE_ANON_KEY` | variable | anon key (public by design; protected by RLS) |
| `API_URL` | variable | the Worker URL printed by the first API deploy (§3, step 2) |

Until all of these exist, the **Deploy** workflow skips itself with a warning instead of failing.

## 3. First deploy (by hand, in this order)

```bash
# 1. Database: apply every migration (never the local seed)
npx supabase@2 link --project-ref <ref>
npx supabase@2 db push

# 2. API
cd apps/api
pnpm exec wrangler secret put SUPABASE_URL --env production
pnpm exec wrangler secret put SUPABASE_ANON_KEY --env production
pnpm exec wrangler secret put SUPABASE_SERVICE_ROLE_KEY --env production
pnpm exec wrangler deploy --env production        # prints https://lunhaw-api-production.<account>.workers.dev
curl https://lunhaw-api-production.<account>.workers.dev/v1/places | head -c 300   # expect 26 places

# 3. Website
pnpm exec wrangler pages project create lunhaw --production-branch main
cd ../..
NEXT_PUBLIC_API_URL=https://lunhaw-api-production.<account>.workers.dev \
NEXT_PUBLIC_SUPABASE_URL=https://<ref>.supabase.co \
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon key> \
pnpm --filter web build
pnpm --filter @lunhaw/api exec wrangler pages deploy ../web/out --project-name lunhaw --branch main
```

If the Pages name `lunhaw` is already taken, Cloudflare assigns another `*.pages.dev` name. Then update
`CORS_ORIGIN` in `apps/api/wrangler.toml`, the smoke-test URL in `.github/workflows/deploy.yml`, and the Supabase Site
URL and Redirect URL to match, and redeploy the API.

After this, set the `API_URL` variable. From then on every push to `main` deploys automatically (**Deploy** workflow:
database → API → website → smoke test).

## 4. Launch checklist (E-MR-02)

- [ ] Privacy Notice and Terms of Use (`/privacy`, `/terms`) reviewed by someone qualified in Philippine law.
- [ ] Custom SMTP configured, and a test sign-up confirmation email received at a non-team address.
- [ ] `curl $API_URL/v1/places` returns 26 places, none `VERIFIED` (until the worksheet is used, §5).
- [ ] Release rehearsal (E-MR-01) on the live site, on a phone and a desktop:
  - [ ] **UJ-001** sign up → confirm email → `/home` → Libraries → open a library → hours show *Not available yet*, the facility notice is shown → save it → it appears under *Saved*.
  - [ ] **UJ-002** open a park → *How to go there?* → *Enter starting location* → pick *Cubao* → walking estimate shown and labelled *Estimate*; public transport says it isn't available yet.
  - [ ] **UJ-003** deny the location prompt → you're offered manual entry; *My Location* → choose a city → only that city's places are listed.
- [ ] Footer newsletter: sign up once; the row appears in Supabase `newsletter_signups`.
- [ ] Security headers present: `curl -I https://lunhaw.pages.dev` shows `content-security-policy` and `x-frame-options: DENY`.
- [ ] GitHub repository visibility decided (it's private today; the site works either way).

## 5. Verifying places after launch (Estimate → Verified)

1. Confirm a place with an official source (the facility, its LGU website or a phone call).
2. In `docs/verification-worksheet.csv`, fill that row's `confirmed_by`, `confirmed_on` (YYYY-MM-DD),
   `official_source_name` (shown to users) and `official_source_url` (https).
3. Run `node scripts/data/verification-migration.mjs`. It checks every row and writes a new
   `supabase/migrations/000NN_verify_places_<date>.sql`.
4. Clear those rows' confirmation columns, open a PR, merge. The Deploy workflow applies the migration.

Opening hours and amenities, and adding a held-back reading center, are separate data changes: write a migration that
inserts the confirmed rows with a `VERIFIED` `verification_meta` (source, date, person). Never mark anything `VERIFIED`
without a person having checked it (`INV-001`).

## 6. Operating

| Task | How |
|---|---|
| Delete an account (privacy request) | Supabase → Authentication → Users → delete. Reply within 30 days. |
| Unsubscribe from the newsletter | `delete from newsletter_signups where lower(email) = lower('<email>');` |
| Export the newsletter list | Supabase → Table editor → `newsletter_signups` → export CSV |
| Roll back the website | Cloudflare → Pages → lunhaw → Deployments → *Rollback* |
| Roll back the API | `pnpm --filter @lunhaw/api exec wrangler rollback --env production` |
| Database changes | Forward-only: write a new migration; never edit an applied one |
| Supabase free-tier pause | The `supabase-keepalive` workflow pings the project; give it `SUPABASE_URL`/`SUPABASE_ANON_KEY` secrets |

## 7. Local development

```bash
pnpm install
pnpm --filter @lunhaw/api dev                 # API on :8787 with in-repo fixtures (no database needed)
pnpm --filter web dev                         # website on :3000; mock accounts work only in development
pnpm --filter web build && pnpm --filter web start   # preview the exported site as Cloudflare Pages serves it
DATABASE_URL=postgres://… bash scripts/test-migrations.sh   # apply all migrations to a disposable PostGIS DB
```
